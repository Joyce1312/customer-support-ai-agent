One design decision I made was to separate the agent’s capabilities into specialized tools rather than putting all of the logic directly into the agent prompt. For example, I used the Bedrock Knowledge Base for product and policy information, AgentCore Gateway tools for order and refund operations, and the Code Interpreter for loyalty discount calculations. This allowed the agent to select the appropriate tool depending on the customer’s request and kept deterministic calculations separate from the language model’s reasoning.
One challenge I encountered involved the loyalty discount tool. The Code Interpreter correctly calculated a Gold member’s discount on a $150 order with 4,250 points. It returned a $40 points discount, an $11 tier discount, a $99 final total, 99 points earned, and 349 remaining points. However, the model initially recalculated some of these values when generating its final response, incorrectly applying the 10% Gold discount to the original $150 instead of the $110 subtotal after the points discount. I verified the Code Interpreter output directly and used runtime logs to confirm that the tool was returning the correct values. I then updated the system prompt to instruct the agent to treat calculated tool results as authoritative and to apply the discounts sequentially. After redeploying, the agent returned the correct results.
For a production environment, I would add stronger authentication and authorization, more comprehensive error handling, monitoring and alerting, and automated tests for each tool. I would also add guardrails for sensitive customer actions such as refunds and improve observability so tool calls and failures can be traced. Finally, I would expand the knowledge base and integrate the agent with real customer, inventory, shipping, and order-management systems.
